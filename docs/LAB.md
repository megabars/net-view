# Локальная сетевая лаборатория

Небольшое приложение для проверки будущего инспектора сетевого трафика. Сервер принимает HTTP, TCP и UDP только на `127.0.0.1`. Клиенты отправляют данные и проверяют, что сервер вернул их без изменений. Внешние адреса и интернет для работы не нужны.

Нужен Python 3 с поддержкой Tk для графического окна. Дополнительные Python-пакеты не требуются. Если Tk недоступен, сервер и консольный клиент можно использовать отдельно.

## Запуск окна

```sh
python3 network_lab.py
```

Приложение открывает окно и запускает свой сервер отдельным дочерним процессом. При закрытии окна этот сервер завершается. Кнопки сценариев отправляют запросы из Python-клиента; его PID позволяет найти процесс в инспекторе.

Если стандартные порты заняты, окно может запустить свой сервер на свободных портах:

```sh
python3 network_lab.py gui --http-port 0 --tcp-port 0 --udp-port 0
```

Назначенные порты будут показаны в окне.

## Отдельные сервер и клиент

В первом терминале:

```sh
python3 network_lab.py server
```

По умолчанию HTTP слушает порт `18765`, TCP — `18766`, UDP — `18767`. Первая строка вывода сервера — JSON с `ready`, PID и фактическими портами. Остановить сервер можно сочетанием Ctrl+C.

Во втором терминале запустите все сценарии:

```sh
python3 network_lab.py client --scenario all
```

Клиент выводит JSON-массив результатов: имя сценария, протокол, PID клиента, адрес, размеры отправленных и полученных данных, SHA-256, результат сравнения `matched` и сокращенный исходящий текст `preview`. Успешный обмен имеет `matched: true` и одинаковые `sent_bytes` / `received_bytes`.

Доступны отдельные сценарии:

```sh
python3 network_lab.py client --scenario http
python3 network_lab.py client --scenario http-large
python3 network_lab.py client --scenario tcp
python3 network_lab.py client --scenario udp
```

`http-large` отправляет не менее 64 КиБ. Каждый новый запуск команды клиента создает отдельный процесс с новым PID — это удобно для проверки привязки трафика к процессам.

Чтобы подключить окно к уже запущенному серверу на стандартных портах:

```sh
python3 network_lab.py gui --connect
```

Для свободных портов запустите сервер с нулями и возьмите назначенные порты из его первой строки:

```sh
python3 network_lab.py server --http-port 0 --tcp-port 0 --udp-port 0
python3 network_lab.py client --scenario all --http-port 50101 --tcp-port 50102 --udp-port 50103
```

Числа `50101`, `50102`, `50103` в примере необходимо заменить фактическими портами сервера.

## Что смотреть в инспекторе

На macOS локальный обмен проходит через интерфейс `lo0`. Выбирайте его и фильтруйте трафик по портам сервера или PID нужного процесса. Сервер и консольный клиент имеют разные PID.

Откройте [страницу лаборатории](http://127.0.0.1:18765/) в Safari, чтобы получить браузерный HTTP-запрос. Этот GET принадлежит процессу браузера; запросы кнопок окна принадлежат Python-клиенту. Если HTTP-порт изменен, замените его в адресе страницы.

Размеры в результатах — байты прикладного тела, без HTTP-заголовков, TCP framing и сетевых заголовков. Передача 64 КиБ не гарантирует фиксированное число пакетов: система может разбивать и объединять данные. Проверяйте содержимое и процессы, не ожидайте определенного количества пакетов.

Обмен идет без TLS. Это лаборатория для localhost; сервер не предоставляет доступ с других компьютеров.

## Протоколы

- HTTP: `POST /echo` возвращает тело запроса без изменений; `GET /health` возвращает JSON со статусом `ok` и PID сервера; `GET /` — простую HTML-страницу. Неизвестный путь возвращает `404`.
- TCP: сообщение — длина тела в четырех байтах big-endian, затем тело JSON в UTF-8. Сервер возвращает тот же frame.
- UDP: сервер возвращает полученную датаграмму без изменений.

## Проверка

```sh
python3 -m unittest discover -s tests -v
```

Тесты запускают отдельный сервер на свободных локальных портах, проверяют точное эхо для трех протоколов, большое HTTP-тело, TCP-сообщение, отправленное частями, и консольные клиенты с разными PID. Графическое окно при проверке не открывается.
