# Разбор пакетов и формат сеанса

`netview.protocols.decode_frame()` сохраняет исходные байты и метаданные
`CapturedFrame` независимо от успеха разбора. Поля PID и effective PID берутся
только из кадра; порт не используется для определения владельца.

Поддерживаются Ethernet (до четырёх VLAN-тегов), NULL/LOOP, RAW, IPv4/IPv6,
Linux cooked v1/v2. Для IPv4/IPv6 разбираются TCP и UDP; ICMP/ICMPv6 и ESP
обозначаются отдельно. IPv6 hop-by-hop, routing, destination options и AH
пропускаются с проверкой длины, максимум 16 заголовков. IP-фрагменты не
собираются и не интерпретируются как TCP/UDP. Контрольные суммы не проверяются:
при локальном захвате данные до checksum offload могут не содержать итоговую
контрольную сумму.

Усечение, неизвестные форматы и неподдерживаемые фрагменты попадают в `issues`.
HTTP/1.x обозначается только при наличии узнаваемой стартовой строки, Host —
только из захваченного заголовка. TLS-данные не расшифровываются. Отсутствие
распознанного TLS-заголовка не доказывает отсутствие шифрования.

`Session` хранит по умолчанию до 10 000 кадров и 32 МиБ захваченных байтов.
`total_bytes` — сумма длин исходных захваченных кадров, `wire_length` —
оригинальная длина кадра из метаданных (или захваченная длина, если оригинальная
не сообщена). `sent_bytes`/`received_bytes` — наблюдавшиеся байты полезной нагрузки,
включая повторные наблюдения. Направление определяется метаданными in/out;
при неизвестном направлении «sent» относится к первому источнику соединения.
`packet_count` считает каждое наблюдение, в том числе повторы. Достижение лимита
останавливает добавление новых кадров, уже записанные кадры сохраняются.

Соединение определяется протоколом, парой адресов и портов, PID и effective PID.
Обратное направление попадает в то же соединение. Новый TCP SYN с другой
начальной последовательностью или SYN после закрытия создаёт новое соединение.
Повтор SYN с тем же sequence number остаётся в текущем соединении. Полностью
надёжно различать повтор и новое соединение с идентичными исходными номерами
последовательности при отсутствии его завершения нельзя.

TCP собирается отдельно в каждом направлении с учётом SYN и перехода sequence
number через 2³². Поддерживается окно относительных sequence number ±2³¹ байтов,
достаточное для ограниченного сеанса. Повторные и перекрывающиеся байты входят
в восстановленные данные один раз; факт повторов указывается явно. При конфликте
приоритет имеет сегмент с меньшим начальным sequence number, затем более раннее
наблюдение. Конфликт отмечается в `issues`. Пропуски разделяют данные на отдельные
части; части не склеиваются. Отсутствие начального SYN или конечного FIN/RST
также указывается: восстановленные данные не объявляются полным сообщением.
UDP возвращается как отдельные датаграммы, а не как фиктивный поток.

Файл `.netview.json` — JSON с `format: "netview-session"`, `version: 1`,
лимитами, флагом достигнутого лимита, массивом `notes` и массивом `frames`.
`notes` сохраняет сообщения о потерях очереди/ядра и прочих известных
ограничениях полноты захвата: максимум 64 строки по 1024 символа. Поле
необязательно для чтения старых файлов версии 1. Каждый кадр содержит
все исходные поля `CapturedFrame`; `data` кодируется base64. Производные поля
(разобранные заголовки, соединения, потоки) заново вычисляются при открытии.
Запись атомарная через временный файл в том же каталоге. Загрузка проверяет
версию, типы, длины метаданных, base64, число кадров и бюджет захваченных байтов.
Абсолютные верхние пределы: 100 000 кадров, 128 МиБ захваченных байтов и
320 МиБ файла. Метаданные имён процессов ограничены 256 символами,
интерфейса — 128, направления — 32. Некорректный файл отклоняется целиком.

Проверки на искусственных пакетах: `tests/test_protocols.py` и
`tests/test_session.py`. Они не являются проверкой живого захвата и не требуют
macOS, сетевых соединений или повышенных прав.
