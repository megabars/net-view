# Проверка переноса на Java 21

Сравнительные фикстуры в `src/test/resources/parity/` получены эталонным
Python-кодом `netview.session.Session`. Декодирование, сборка потоков и захват
в инспекторе выполняются Java-кодом; Python используется отдельной лабораторией
и сравнительными проверками.

| Фикстура | Происхождение | Пакеты | Соединения | Байты кадров |
| --- | --- | ---: | ---: | ---: |
| `synthetic-demo` | Копия `tests/fixtures/lab_demo.netview.json`; синтетический пример | 20 | 6 | 1 415 |
| `synthetic-stress` | Детерминированная генерация; синтетический пример | 105 | 21 | 141 665 |
| `real-lab` | Копия `results/live-20261028-201526-2bad5b1b.netview.json`; реальный контролируемый loopback-трафик Python-лаборатории | 60 | 4 | 137 062 |

Сеанс `real-lab` был захвачен Python-прототипом 28 октября 2026 года после
аутентификации пользователя в Terminal. Его чтение Java-приложением проверяет
совместимость с существующим захватом; оно не подтверждает новый живой
захват Java. Содержимое фикстуры ограничено контролируемым `network_lab.py`.
Сам файл лаборатории в ходе переноса не меняется.

`synthetic-stress` содержит двоичный поток больше 128 КиБ с фиксированной
перестановкой сегментов, повторы, частичные и конфликтующие перекрытия,
пропуски начала/середины/хвоста, переход sequence number через 2³²,
SYN/ACK до SYN, повторное использование закрытого соединения, неизвестный
и отличающийся PID, IPv6, отдельные UDP-датаграммы, несколько link types,
усеченные и неизвестные кадры и неподдерживаемый IPv4-фрагмент.
Это набор конкретных случаев, а не заявление о полном покрытии протоколов.

Файлы `*.expected.json` фиксируют SHA-256 исходного файла и эталонный результат:

- метаданные, исходные байты и полезную нагрузку каждого пакета;
- адреса, порты, протокол, TCP sequence/flags, размеры и принадлежность соединению;
- метаданные соединений, число пакетов и счетчики прикладных байтов;
- отдельные части потоков, длины, SHA-256, число и категории предупреждений;
- ограничения сеанса, признак достижения лимита и диагностические заметки.

Точное английское написание предупреждений не является контрактом. Сравнение
сохраняет число и смысловые категории предупреждений, а для частей потоков —
границы, имена, длины и байты через SHA-256. Разрывы не маскируются объединением
частей. Счетчики соединений учитывают наблюдаемые полезные нагрузки, включая
повторы; восстановленные потоки учитывают пересекающиеся байты один раз.

## Повторение

Создание эталонов текущим Python-кодом:

```sh
python3 tools/export_parity_fixtures.py
```

Запуск сравнительного теста (JDK 21):

```sh
mvn -Dtest=netview.parity.PythonParityTest test
```

`PythonParityTest` сверяет все три сеанса с Python-эталонами, сохраняет их
Java-кодом в `target/parity-java/`, повторно открывает Java-кодом и сравнивает
метаданные и исходные кадры. Затем отдельный Python-процесс проверяет чтение
Java-файлов существующим Python-загрузчиком:

```sh
for name in synthetic-demo synthetic-stress real-lab; do
  python3 tools/export_parity_fixtures.py \
    --verify-java-output "target/parity-java/$name.netview.json" \
    --expected "src/test/resources/parity/$name.expected.json"
done
```

При работе без доступа к внешнему Maven-репозиторию нужно использовать настройки
и локальный кэш зависимостей, описанные в README. Сгенерированные файлы в `target/`
являются результатами теста, эталоны лежат в `src/test/resources/`.

### Кнопки живого захвата и повторный запуск

Пользователь запустил `.app` из своего Terminal после `sudo -v`.
Дальнейшие выбор PID, нажатия «Начать захват» / «Остановить», создание нового
сеанса и сохранение выполнены через интерфейс, без подмены кнопок CLI-захватом.
Независимый процесс `tools/gui_capture_lab.py` (PID 67498) отправлял сообщения
только после появления статуса «Захват активен».

В двух первых циклах захват и остановка работали, но итоговый счетчик ядра
оставался неизвестным. Обнаружен и исправлен дефект: раннее закрытие stdout
могло оборвать финальную запись tcpdump. Теперь после отмены канал дочитывается
без добавления пакетов, сначала завершается пишущий процесс, а обертке дается
ограниченное время дождаться его. Принудительное завершение остается ограниченным
по времени; отсутствие статистики по-прежнему не подменяется нулем.

Новый тест с реальными процессами воспроизводит дефект: дочерний процесс при
завершении записывает больше емкости канала, затем итоговую статистику.
На старом коде счетчик отсутствует; после исправления он получен, оба процесса
завершены. Полная Java-сборка после исправления: 47 тестов, без ошибок и пропусков.

После обновления `.app` выполнены еще два цикла в одном окне:

- каждый цикл: 60 пакетов, четыре соединения, 137 062 байта кадров, `lo0`;
- HTTP, большой HTTP, TCP и UDP: 16 точных сверок тел запросов/ответов суммарно;
- после каждой остановки окно показывает потери очереди 0 и ядра 0;
- процессы tcpdump и их обертки отсутствуют после остановки;
- четыре дополнительных обмена при остановленном захвате не увеличили счетчик
  60 и отсутствуют в сохраненных кадрах;
- новый сеанс не содержит сообщения предыдущего цикла;
- файлы сохранены через системный диалог; Java и Python восстанавливают одинаковые
