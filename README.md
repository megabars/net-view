# Net View 0.5.0 — сетевой инспектор на Java 21

Основное приложение — **Java 21 + JavaFX**. Оно показывает процессы,
соединения, отдельные пакеты, HEX и восстановленные прикладные данные.
Для работы инспектора Python не требуется. Отдельный **`network_lab.py`**
создает контролируемый тестовый трафик и остается на Python без изменений.

План, требования и границы переноса — в [SPEC.md](SPEC.md).
Версия 0.5.0 — MVP с живым захватом на macOS; установщики и захват
на Windows/Linux пока не входят в релиз.

## Сборка и запуск

Нужны **JDK 21** и **Maven 3.9+**. JavaFX, Jackson и тестовые зависимости
загружаются Maven; отдельно устанавливать JavaFX не нужно. При первой сборке
нужен доступ к репозиторию зависимостей. Сборка выполняет Java-тесты и создает
приложение в `target/` вместе с библиотеками в `target/lib/`.

На macOS проверьте, что Maven и приложение используют JDK 21:

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH="$JAVA_HOME/bin:$PATH"
java -version
mvn -version
./scripts/build.sh
./scripts/run.sh
```

Просмотр сохраненного сеанса не требует прав администратора:

```sh
./scripts/run.sh --open tests/fixtures/lab_demo.netview.json
./scripts/run.sh --open src/test/resources/parity/real-lab.netview.json
```

Первый пример — явно **синтетическая** демонстрация. Второй открывает имеющийся
реальный захват контролируемой лаборатории, сделанный Python-прототипом;
его чтение не является новым живым тестом Java-захвата.

`run.sh` собирает приложение, если JAR еще отсутствует. После изменения исходников
выполните `build.sh` заново. Для переноса готовой сборки сохраняйте JAR и
`target/lib/` вместе. Нативные библиотеки JavaFX зависят от ОС: сборку следует
выполнять на той системе, где приложение будет запускаться.

### Windows и Linux: сохраненные файлы

Модели, чтение сеансов и JavaFX-интерфейс отделены от macOS-захвата.
На Windows при установленных JDK 21 и Maven:

```bat
mvn package
scripts\run.cmd --open tests\fixtures\lab_demo.netview.json
```

На Linux используются те же `scripts/build.sh` и `scripts/run.sh`, что на macOS.
Чтение файлов доступно без запуска сетевого захвата. **Живой захват реализован
только для macOS**; адаптеров Windows/Linux пока нет. Запуск интерфейса на этих
двух ОС в текущей проверке не подтвержден.

Для сборки без сети все зависимости должны быть заранее загружены в локальный
кэш Maven. Тогда можно выполнить `./scripts/build.sh -o` или `mvn -o package`
на Windows. `.mvn/maven.config` уже выбирает кэш проекта `.cache/m2/`
и настройки `.mvn/settings.xml`, поэтому дополнительные параметры репозитория
не нужны. Настройки проекта заменяют личный `~/.m2/settings.xml`. Готовое
приложение и просмотр файлов работают без скачивания зависимостей.

## Живой захват на macOS

Из Terminal в папке проекта:

```sh
./"Start Net View.command"
```

Скрипт сначала собирает Java-приложение, затем предлагает аутентификацию через
`sudo` и запускает обычное пользовательское окно. Только системный Apple
`tcpdump` получает доступ к BPF и сбрасывает повышенные права после открытия
устройства. Net View не читает и не хранит пароль, не меняет права устройств
и системные настройки.

Разрешение связано с Terminal запуска. Если оно истекло, повторите запуск
из Terminal. Интерфейс целиком через `sudo` запускать не нужно.

1. Найдите процесс по названию или PID и выберите его.
2. Нажмите **«Начать захват»** и создайте сетевую активность в приложении.
3. Выберите соединение и пакет. Внизу доступны детали, HEX исходного кадра,
   данные пакета и собранные данные соединения.
4. Нажмите **«Остановить»**, дождитесь завершения и сохраните сеанс.

Файл `.netview.json` версии 1 содержит исходные кадры, PID, интерфейсы,
направления и заметки о потерях. Python- и Java-версии читают этот формат
в обе стороны; проверка совместимости описана ниже.

**«Открыть сеанс»** также читает pcapng с Enhanced Packet Blocks и сохраняет
Apple PID metadata при ее наличии. Classic `.pcap`, Simple Packet Blocks и
raw PKTAP внутри файла пока не поддержаны. Сохранение выполняется в формате
Net View JSON.

Поиск процессов не использует аргументы командной строки. Список обновляется
кнопкой. Выбирается один PID; вспомогательные процессы браузера автоматически
не объединяются. При захвате учитываются PID и effective PID, если macOS
передала соответствующие метаданные.

## Отдельная Python-лаборатория

Для лаборатории нужен **Python 3.11+**; для ее окна — Tk. Сторонние Python-пакеты
не нужны. В инспекторе есть кнопка **«Тестовый клиент»**, которая запускает
лабораторию отдельно. Ее также можно запустить напрямую:

```sh
python3 network_lab.py gui --http-port 0 --tcp-port 0 --udp-port 0
```

1. Найдите **PID клиента** в окне лаборатории.
2. Обновите процессы в инспекторе, выберите этот PID и начните захват.
3. Нажмите **«Все сценарии»** в лаборатории.
4. Остановите захват и проверьте HTTP, большой HTTP-запрос, TCP и UDP во вкладке
   **«Собранные данные»**. Маркер — `NET-VIEW-TEST`, адреса — `127.0.0.1`.

HTTP отображается как данные TCP: заголовки и тело доступны в потоке,
а столбец протокола обозначает транспорт. UDP сохраняет границы датаграмм.
Прикладные счетчики включают наблюдаемые повторы; TCP-сборка учитывает
пересекающиеся байты один раз и обозначает разрывы отдельными частями.

Подробная инструкция лаборатории: [docs/LAB.md](docs/LAB.md).

## Границы текущей версии

- HTTPS/TLS не расшифровывается: доступны адреса, размеры и исходные байты.
- Домен по IP не угадывается. HTTP Host можно прочитать в открытых заголовках.
- Захват начинается с нажатия кнопки; уже прошедшие данные недоступны.
- Неизвестные PID не назначаются по порту. Пакеты без подходящих метаданных
  не попадают в захват выбранного процесса.
- Нет сборки IP-фрагментов и полноценного разбора HTTP/2, HTTP/3/QUIC.
- По умолчанию сеанс ограничен 10 000 кадрами / 32 МиБ исходных байтов.
  Это не полный размер памяти процесса; очередь захвата тоже ограничена.
- Предпросмотр данных ограничен 256 КиБ полезной нагрузки; общий объем
  сформированного текста потока также ограничен. Полные исходные байты
  сохраняются в сеансе; потери очереди и ядра показываются отдельно.
- Готовые установщики, подпись для распространения/notarization и автоматическое
  обновление пока не входят в поставку. Локальная `.app` используется для
  проверки на macOS.

## Проверки

Подтверждено на macOS: сборка `mvn -o package` на JDK 21 и **47 Java-тестов**;
отдельно прошли **59 Python-тестов** и чтение трех Java-файлов существующим
Python-кодом.
Пользователь также выполнил новый живой Java-захват лаборатории: **60 пакетов,
4 соединения, 137 062 байта кадров**, потерь очереди и ядра нет. В HTTP,
большом HTTP, TCP и UDP все восемь тел запроса/ответа совпали с точными длинами
и SHA-256 клиента; потоки Java и Python совпали. Компактный отчет —
[docs/JAVA_LIVE_RESULT.json](docs/JAVA_LIVE_RESULT.json).

Основной сценарий JavaFX проверен в локальной `.app`: открыт новый Java-сеанс, видны
4 соединения и 60 пакетов, HTTP/JSON обоих направлений, две отдельные
UDP-датаграммы и HEX; проверен поиск процессов. Сохранение и повторное открытие
через GUI подтверждены: контрольная копия полностью сохраняет данные сеанса.
Кнопки начала/остановки живого захвата проверены в двух циклах одного окна:
по 60 пакетов, нулевые потери, точные данные в обе стороны. После остановки
новый трафик не добавляется, повторный запуск работает. Исправлено преждевременное
закрытие канала, из-за которого могла теряться итоговая статистика ядра.
Отчет — [docs/JAVA_GUI_RESULT.json](docs/JAVA_GUI_RESULT.json). Точный объем
визуальной проверки указан в [docs/JAVA_VERIFICATION.md](docs/JAVA_VERIFICATION.md).

Java-тесты выполняются при `./scripts/build.sh`; отдельно их можно запустить
командой `mvn test`. Они проверяют декодирование, TCP-сборку, лимиты и формат
сеанса, pcapng/метаданные и жизненный цикл адаптера на управляемых тестовых
данных. Сравнительные тесты используют Python-эталоны трех сохраненных сеансов,
включая существующий реальный лабораторный захват.

Проверка чтения файлов, записанных Java-тестом, существующим Python-кодом:

```sh
for name in synthetic-demo synthetic-stress real-lab; do
  python3 tools/export_parity_fixtures.py \
    --verify-java-output "target/parity-java/$name.netview.json" \
    --expected "src/test/resources/parity/$name.expected.json"
done
```

Тесты отдельной лаборатории и Python-эталона:

```sh
python3 -m unittest discover -s tests -v
```

Интеграционные тесты лаборатории требуют разрешенных локальных сокетов.
Сам Python-инспектор сохранен как эталон переноса: `python3 net_view.py`
или `python3 net_view.py --open путь/к/capture.netview.json`. Он требует Tk
и больше не является основным приложением.

Новый живой тест **Java-захвата** запускается на macOS из Terminal:

```sh
./scripts/check-live-java.sh
```

Скрипт запрашивает аутентификацию для системного tcpdump, запускает отдельную
Python-лабораторию и Java-захват, сверяет точные длины и SHA-256 сообщений
HTTP, большого HTTP, TCP и UDP в обе стороны. Он сохраняет отчет и сеанс
в `results/java-live-*`. Java-инспектор работает без Python; Python используется
здесь для независимой проверки контролируемых обменов.

Чтение старого захвата, тест на синтетических данных и новый живой захват
фиксируются отдельно. Подтвержденные результаты и команды сравнительной
проверки — в [docs/JAVA_VERIFICATION.md](docs/JAVA_VERIFICATION.md).
Исторические результаты Python-прототипа — в
[docs/MVP_CHECKS.md](docs/MVP_CHECKS.md). Подробности формата и захвата:
[capture](docs/CAPTURE.md), [protocols/session](docs/PROTOCOLS.md).
