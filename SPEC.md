# Net View — MVP и перенос на Java + JavaFX

Текущая версия: **0.5.0**, тег выпуска `v0.5.0`.

## Решение о переносе — 28 октября 2026

Основное приложение переносится на Java 21 + JavaFX. `network_lab.py` и его
интеграционные тесты остаются на Python без изменений. Python-инспектор временно
сохраняется как эталон; его интерфейс больше не является основным направлением
развития. Сохраненные `.netview.json` версии 1 должны открываться новой версией,
а сохраненные Java файлы — читаться существующим Python-кодом.

### Целевая архитектура

- Maven-проект: Java 21, JavaFX, JUnit; зафиксированные версии зависимостей.
- `netview.model`: независимые от ОС модели кадра, пакета, соединения и потока.
- `netview.protocol` / `netview.session`: Java-разбор IPv4/IPv6/TCP/UDP,
  сборка потоков, ограничение памяти, чтение и атомарная запись сеансов.
- `netview.capture`: интерфейс адаптера, Java-парсер pcapng и адаптер macOS,
  запускающий системный tcpdump. Python не нужен для работы инспектора.
- `netview.ui`: JavaFX, виртуализированные таблицы, фоновые операции ввода/вывода,
  обновление экрана пакетами и ограниченный предварительный просмотр.
- Python требуется только для запуска отдельной лаборатории и сравнительных тестов.

Захват на Windows/Linux остается отдельным будущим этапом. Чтение файлов,
модели и интерфейс сразу отделены от macOS. Приложение не запускается от root;
доступ к пакетам по-прежнему получает только системный процесс захвата.

### Статус переноса

Функциональный перенос MVP реализован на Java 21 + JavaFX 21.0.13. Основной
запуск — `Start Net View.command` / `scripts/run.sh`. `network_lab.py` сохранен
без изменений; Python-инспектор остается сравнительным эталоном.

Подтверждено 28 октября 2026:

- 47 Java-тестов и 59 тестов Python проходят; Java 21, macOS Apple Silicon.
- Три контрольных сеанса совпадают с Python по пакетам, метаданным и SHA-256
  потоков; файлы Java читаются Python без изменения данных.
- Новый живой Java-захват: 60 пакетов, четыре соединения, 137 062 байта кадров,
  PID 55478, `lo0`, входящие и исходящие данные. Все восемь тел HTTP/большого
  HTTP/TCP/UDP совпали с лабораторией; потери очереди и ядра — ноль.
- В JavaFX открыт этот новый сеанс; визуально проверены соединения, HTTP/JSON,
  отдельные UDP-датаграммы, HEX и фильтрация процессов.

После разблокировки macOS проверены «Сохранить» и повторное «Открыть сеанс»
через системные диалоги JavaFX. Контрольная копия содержит те же 60 пакетов,
четыре соединения, метаданные и восемь частей потоков; JSON и Java-разбор
полностью совпадают с исходным сеансом.
Кнопки начала и остановки живого захвата проверены в двух циклах одного окна.
Каждый цикл дал 60 пакетов / четыре соединения; все 16 тел запросов и ответов
совпали с независимыми SHA-256 лаборатории. Потери очереди и ядра — ноль.
После остановки новые сообщения не попадали в сеанс, процессы захвата завершались;
повторный запуск и сохранение через GUI работают.

При этой проверке исправлена потеря итоговой статистики при остановке:
канал дочитывается до завершения писателя, процесс захвата завершается раньше
обертки, ожидание ограничено. Новый регрессионный тест воспроизводит дефект
на старом коде и проходит после исправления. Подробные результаты:
[JAVA_VERIFICATION.md](docs/JAVA_VERIFICATION.md).

Локальная `.app`-сборка создана для проверки окна; это не подписанный установщик
для распространения. Поддержка захвата Windows/Linux, установщики и расшифровка
HTTPS не входят в выполненный перенос. Далее: проверить длительную нагрузку
и сторонние приложения,
подготовить распространение на macOS, затем реализовать и проверить адаптеры
захвата Windows и Linux. Ниже сохранена история Python-прототипа.

## Цель

Настольное приложение для macOS: выбрать процесс, увидеть его реальные сетевые
соединения, отдельные пакеты и восстановленные данные. Сохранять сеанс и открывать
его позднее. `network_lab.py` — отдельный тестовый стенд, не сам инспектор.

## Границы первой версии

Входит:

- список процессов с названием и PID, поиск и обновление;
- захват TCP/UDP выбранного PID на macOS, включая loopback;
- использование метаданных macOS для определения владельца пакета;
- отображение IP/портов, направления, времени, интерфейса и размеров;
- группировка пакетов в соединения;
- детали пакета, HEX и текст полезной нагрузки;
- восстановление TCP-потоков отдельно по направлениям с учетом порядка,
  повторных передач и обнаруживаемых пропусков;
- доступные HTTP/1.x данные в восстановленном потоке, UTF-8 и JSON там,
  где формат известен; неизвестные и зашифрованные данные не выдаются за текст;
- сохранение/загрузка локального сеанса вместе с PID и исходными байтами;
- ограничение памяти и явное сообщение о потерях/достигнутом лимите;
- основной инспектор работает без Python; отдельная лаборатория — на Python stdlib.

Не входит:

- расшифровка TLS/HTTPS, MITM-сертификаты;
- полноценный разбор HTTP/2, HTTP/3, QUIC, gRPC и любых неизвестных протоколов;
- автоматическое объединение всех вспомогательных процессов в одно приложение;
- восстановление отсутствовавших при захвате пакетов;
- полноценная сборка IP-фрагментов;
- блокировка/редактирование трафика, правила файрвола;
- готовые адаптеры захвата для Windows/Linux, подписанный установщик.

Safari может использовать вспомогательный сетевой процесс: MVP показывает PID
из метаданных, в том числе effective PID, и не обещает полный охват браузера при
выборе только главного процесса. Домены показываем только при наличии данных,
которые позволяют установить их; IP не заменяем догадкой о назначении сервера.

## Архитектура Python-прототипа (эталон переноса)

1. `net_view.py` и `netview/ui.py`: интерфейс Python/Tk, обычные права пользователя.
2. `netview/capture.py`: адаптер macOS. Системный `/usr/sbin/tcpdump` захватывает
   `pktap,all` и передает pcapng приложению. Метаданные сохраняют владельца пакета.
   Парсер проверяет границы блоков; ошибки захвата отображаются пользователю.
3. `netview/models.py`: независимая от ОС модель захваченного кадра.
4. `netview/protocols.py` и `netview/session.py`: разбор кадров, TCP-сборка,
   ограниченная память и формат сеанса; код не зависит от macOS.
5. `network_lab.py` и `tests/`: контролируемые данные и проверки.

Повышенные права получает процесс захвата, интерфейс не запускается от root.
На этом компьютере BPF доступен только root. Для первого запуска потребуется
ввод пароля самим пользователем в Terminal. Пароль не хранится и не запрашивается
в форме нашего приложения. Не меняем права `/dev/bpf*` и системные настройки.

Будущая переносимость: адаптеры Windows/Linux должны выдавать ту же модель
кадра. Чтение сеансов и разбор протоколов не зависят от способа захвата.

## Ограничения качества и достоверности

Все счетчики четко различают длину кадра и прикладные байты. TCP-поток не
склеивает данные через обнаруженный разрыв без обозначения пропуска. Захват,
начатый посреди соединения, не считается полным. Повторы, loopback и несколько
интерфейсов могут дать дополнительные наблюдения — не скрываем неопределенность.
PID неизвестен, если ОС его не сообщила; подбор PID по одному порту недостаточен.
